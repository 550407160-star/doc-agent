# AI Agent 与 RAG 开发实践指南

## 什么是 RAG

RAG（Retrieval-Augmented Generation，检索增强生成）是一种将外部知识库与大语言模型结合的技术架构。它先把私有文档切分成文本块并向量化存入向量数据库，用户提问时先检索出最相关的文档片段，再把这些片段作为上下文交给大模型生成回答。RAG 的核心价值在于：让大模型能够回答训练数据之外、只存在于企业内部文档中的问题，同时显著降低幻觉，并且可以随时更新知识而不需要重新训练模型。

RAG 的完整链路包括五个环节：文档解析、文本分块、向量化、向量检索、生成回答。文档解析负责从 PDF、Word、Markdown 等格式中提取纯文本；文本分块把长文档切成大小合适的片段，常用的分块策略是按段落或固定长度切分并保留少量重叠；向量化使用 Embedding 模型把文本转为高维向量；向量检索在向量数据库中根据余弦相似度找出最相关的片段；最后生成回答阶段把检索结果拼入提示词交给大模型。

## Agent 与工具调用

Agent 是能自主决策的大模型应用。与一次性问答不同，Agent 可以在多轮循环中自主决定调用哪些工具、按什么顺序调用，从而完成复杂任务。工具调用（Function Calling）是 Agent 的核心能力：开发者把工具以 JSON Schema 的形式声明给模型，模型根据用户问题判断是否需要调用工具、需要传入什么参数，系统执行工具后把结果返回给模型，模型再综合工具结果生成最终回答。

LangGraph 是当前主流的 Agent 编排框架，它把 Agent 流程建模为图：节点是计算单元，边是流转关系，状态在整个图中共享。一个典型的 ReAct Agent 图包含 agent 节点（模型决策）和 tools 节点（执行工具），当模型返回工具调用时流转到 tools 节点，执行完毕再回到 agent 节点，直到模型不再调用工具为止。

## Agent 常见问题与优化

幻觉是 Agent 最需要关注的问题。产生幻觉的主要原因包括：检索到的上下文不相关、模型过度发挥、提示词约束不足。常用优化手段有：提高检索质量、在提示词中明确要求只能依据上下文回答、对输出做自动化校验。

分块大小对检索效果影响明显。分块太小会导致语义不完整，太大则会混入无关信息降低召回精度。实践中一般 300-800 字并保留 10% 左右重叠，再结合具体文档类型调整。

工具调用失败也是高频问题，常见原因有参数格式错误、工具不存在、模型在循环中反复调用同一工具。工程上通过设置最大迭代步数、完善的错误捕获与返回信息来兜底。

## 评测方法

大模型应用上线前必须做效果评测。最实用的评测方式是 LLM-as-Judge：构造一组测试问题与参考答案，批量调用应用获取回答，再让一个评审模型从相关性、忠实度、有用性三个维度打分，最后汇总平均分。忠实度专门用来衡量回答是否忠于知识库内容、是否存在幻觉。评测结果可以持续迭代优化提示词与检索策略。
